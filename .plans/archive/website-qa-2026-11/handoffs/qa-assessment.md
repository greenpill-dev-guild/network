# qa-assessment handoff (PRD-1414)

Session `qa-assessment`, finding 19, decision D1 (keep and fix). Branch `claude/qa-assessment-7191ec`, PR: https://github.com/greenpill-dev-guild/network/pull/42 (open, not merged).

## Changed

- **Question titles sit inside their cards.** Each fieldset legend now uses the standard reset (`float: inline-start; inline-size: 100%`), so it is no longer the fieldset's "rendered legend" that the browser draws across the top border. The block after it clears the float. Fixes September audit F12 / Section 2.8.
- **Two questions take several answers (Afo's decision, 2026-11-07).** "What pulls you toward regeneration right now?" (q1) and "What do you bring today?" (q3, reworded from "What is the strongest thing you bring today?") are checkbox groups with a "Choose all that apply" cue. The other five stay single-choice radios. Afo picked the option "Two questions, each pick counts (Recommended)".
- **Scoring counts every pick.** Every ticked answer gives its path one point. Each question has one option per path, so a question adds at most one point to any path, and a path's score is the number of questions whose answers pointed to it. Single choices score exactly as before; ties still keep the old path order (Learn, Local, Build, Story, Steward) and show the runner-up as "Close second". The result adds one line: "Your answers pointed to Build in 3 of the 7 questions."
- **Progress and submit work with both kinds of group.** A question counts as answered once it has at least one pick; "See your path" unlocks when all seven are answered. The progress live region is rewritten only when the count changes, so a second tick in the same question is not announced again.
- **Answers stay on the device.** Same `localStorage` key (`greenpill.gardenAssessment.v1`); the payload is now `version: 2` with an array of paths per question and the result (`primary`, `secondary`, `score`). Answers saved in the old shape (one path string per question) still restore, including into the new checkbox groups. Restoring never clears a pick already on the page: on a slow load a visitor can tick an answer before the script runs, and that pick stays, saved picks fill only the questions without one, and the merged answers are saved (CodeRabbit's finding on #42, fixed in 0e2f8ab). `data-ga-ready="true"` is still set once listeners are attached and stored state is restored.
- **Copy without em dashes.** Option labels ("Understanding the ideas: regen, public goods, coordination", "Curiosity: I am here to absorb", "Solo for now, reading at my own pace", "The Library: books, podcast, guides"), the five "Close second" labels (now "Learn (browse the Library)" and so on) and the Steward result body. The component has no em or en dashes left.
- **Files.** `packages/website/src/components/page-sections/GardenAssessment.astro`; new `packages/website/src/lib/garden-assessment.ts` (pure scoring and stored-shape rules, imported only by the component and its test; outside the listed file set, but no other session owns it); one new test block in the shared `scripts/public-content-contract.test.ts` (it imports the module dynamically, so the import block that PR #34 edits is untouched); this handoff and `artifacts/qa-assessment/`.
